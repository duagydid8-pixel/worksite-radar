# 급여대장 직종변경 설계

## 목적

급여대장 엑셀을 업로드하면 퇴직공제 직종표 기준으로 `직종` 값을 자동 정리하고, 원본 서식이 유지된 수정 엑셀을 다운로드할 수 있게 한다.

## 적용 위치

- 상위 메뉴: `급여대장`
- 새 서브메뉴: `직종변경`
- 기존 `공수자동보정`, `추가공수 스캔추출` 흐름과 분리한다.

## 입력 파일

- 사용자가 업로드하는 급여대장 `.xlsx`
- 기준 직종표: `C:\Users\bongryong\Desktop\모음\염효양\7. 퇴직공제관리대장\양식\직종표.xlsx`

직종표는 첫 번째 시트의 A열을 허용 직종 목록으로 읽는다. `직종표` 제목 행과 빈 행은 제외한다.

## 급여대장 레이아웃 감지

급여대장 시트에서 상단 15행 안에 있는 `직종`과 `성명` 헤더를 찾는다.

- `직종` 헤더가 있는 열을 변경 대상 열로 사용한다.
- `성명` 헤더가 있는 열은 실제 직원 행 판별에 사용한다.
- 데이터 시작 행은 `직종`/`성명` 헤더 행 다음 행이다.
- 이름이 비어 있거나 헤더성 값인 행은 건너뛴다.
- 여러 시트가 있어도 같은 방식으로 감지 가능한 시트만 처리한다.

## 변경 규칙

각 직원 행의 기존 직종을 공백 제거 후 판정한다.

1. 직종에 `관리자`가 포함되면 `관리자`로 변경한다.
   - 예: `공사관리자`, `품질관리자`, `설계관리자`, `안전관리자` → `관리자`
2. 직종이 `차량운행`이면 `관리자`로 변경한다.
3. 나머지 직종이 직종표에 있으면 그대로 둔다.
   - 예: `배관공`, `보통인부`, `신호수`, `용접공`
4. 나머지 직종이 직종표에 없으면 `보통인부`로 변경한다.
   - 예: `도비공`, `융착공`, `화기/유도원`

변경 전후 값이 같은 행은 결과 목록에 표시하지 않고 파일에도 불필요하게 쓰지 않는다.

## 파일 수정 방식

기존 급여대장 보정 로직처럼 `JSZip`으로 원본 xlsx 내부 XML을 직접 패치한다.

- 셀 값만 바꾼다.
- 서식, 병합, 테두리, 조건부서식, 수식은 보존한다.
- 문자열 셀은 shared string 의존을 피하기 위해 inline string 또는 문자열 셀 XML로 안전하게 저장한다.
- `calcChain.xml`은 제거하고 workbook 재계산 옵션을 설정한다.

## 화면 동작

`직종변경` 화면은 다음 상태를 가진다.

- 업로드 전: `.xlsx` 업로드 영역 표시
- 처리 중: 로딩 표시
- 완료: 변경 요약과 다운로드 버튼 표시

완료 화면에는 아래 정보를 보여준다.

- 전체 변경 건수
- `관리자`로 변경된 건수
- `보통인부`로 변경된 건수
- 변경된 행 목록: 시트명, 행 번호, 성명, 변경 전 직종, 변경 후 직종

다운로드 파일명은 원본 파일명에 `_직종변경완료.xlsx`를 붙인다.

## 오류 처리

- `.xlsx`가 아니면 업로드를 거부한다.
- 급여대장에서 `직종`/`성명` 헤더를 찾지 못하면 처리 실패 메시지를 표시한다.
- 직종표 파일을 읽지 못하면 처리 실패 메시지를 표시한다.
- 변경 대상이 없으면 "변경할 직종이 없습니다"를 표시하되, 원본과 동일한 다운로드는 제공하지 않는다.

## 테스트

핵심 로직은 `src/lib/payrollJobTitleChanger.ts`에 두고 Vitest로 검증한다.

테스트 범위:

- 관리자 접미 직종은 `관리자`로 변경된다.
- `차량운행`은 `관리자`로 변경된다.
- 직종표에 있는 기술인 직종은 유지된다.
- 직종표에 없는 기술인 직종은 `보통인부`로 변경된다.
- `직종`/`성명` 헤더를 감지해 실제 급여대장 행만 변경한다.
- 원본 xlsx 패치 후 변경된 셀을 다시 읽을 수 있다.

## 비범위

- 이름별 수동 직종 매핑
- 퇴직공제관리대장 자동 업로드
- 기존 공수자동보정 계산 규칙 변경
