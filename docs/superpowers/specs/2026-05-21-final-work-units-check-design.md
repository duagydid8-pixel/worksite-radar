# 최종공수확인 설계

## 목적

XERP 월간출퇴근현황에 반영된 날짜별 공수가 실제 출퇴근/PMIS 인아웃/전자카드 기록과 맞는지 빠르게 확인한다. 사용자는 전체 인원을 직접 훑지 않고, 앱이 `확인필요` 건을 먼저 골라 보여주는 것을 목표로 한다.

## 1차 범위

- 대상 파일: XERP `월간출퇴근현황_*.xlsx`
- 최초 확인 기간: 2026년 5월 13일~20일
- PMIS 기록이 없는 날짜는 오류로 판정하지 않고 `PMIS 미업로드`로 표시한다.
- 전자카드 기록이 없는 날짜는 오류로 판정하지 않고 `전자카드 미저장`으로 표시한다.
- 이후 1일~12일 PMIS 기록을 추가하면 같은 화면에서 자동으로 확인 범위를 넓힌다.
- 이후 날짜별 전자카드 기록을 저장하면 같은 화면에서 자동으로 추가 증빙으로 사용한다.

## 사용 위치

기존 `XERP & PMIS` 탭 안에 `최종공수확인` 섹션을 추가한다. 이 탭은 이미 XERP 공수와 PMIS 인아웃 기록을 다루고 있으므로 별도 메뉴보다 자연스럽다.

## 입력 데이터

### XERP 월간출퇴근현황

엑셀은 한 사람당 4개 행을 가진다.

- `출근`: 날짜별 XERP 출근 시간
- `퇴근`: 날짜별 XERP 퇴근 시간
- `공수`: 날짜별 시스템 반영 공수
- `근무시간`: 날짜별 XERP 근무시간

예시 구조:

| 성명 | 구분 | 13일 | 14일 | 15일 | 16일 | 17일 | 18일 | 19일 | 20일 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 김세철 | 출근 | 06:14 | 06:12 | 06:14 |  |  | 06:15 | 06:11 | 06:13 |
|  | 퇴근 | 18:53 | 19:00 | 18:57 |  |  | 17:03 | 19:03 | 17:00 |
|  | 공수 | 1.5 | 1.5 | 1.5 |  |  | 1 | 1.5 | 1 |
|  | 근무시간 | 12:39 | 12:48 | 12:43 |  |  | 10:48 | 12:52 | 10:47 |

### PMIS 인아웃 기록

기존 `XERP & PMIS` 탭에서 로드된 PMIS 데이터를 재사용한다. 사용자가 최종공수확인을 위해 PMIS 파일을 다시 업로드하지 않게 한다.

### 전자카드 기록

전자카드 기록도 최종공수확인의 증빙자료로 사용한다. 기존 `전자카드 조회` 화면은 업로드 후 대조 중심이므로, 새로 날짜별 저장 기능을 추가한다.

저장 기준:

- 현장
- 날짜
- 파일명
- 저장 시각
- 직원별 성명, 생년월일, 전자카드 출근시간, 전자카드 퇴근시간, 인증방식, 소속업체

사용 방식:

- 사용자가 `전자카드 조회` 화면에서 날짜를 선택하고 전자카드 엑셀을 업로드한다.
- `일일 저장` 버튼으로 해당 날짜의 전자카드 기록을 저장한다.
- 최종공수확인 화면은 같은 날짜/이름 기준으로 저장된 전자카드 출근/퇴근 시간을 불러와 증빙자료로 표시한다.
- PMIS와 XERP만으로 판단이 애매한 경우 전자카드 시간이 추가 근거가 된다.

### 가산사유

가산사유가 기존 `XERP & PMIS` 데이터에 있으면 최종공수확인 결과에 함께 표시한다. 사용자는 공수 차이만 보는 것이 아니라, 왜 공수가 그렇게 반영됐는지 바로 확인할 수 있어야 한다.

월간출퇴근현황 파일에는 기본적으로 `출근`, `퇴근`, `공수`, `근무시간` 행만 있을 수 있다. 이 경우 가산사유는 같은 날짜/이름 기준으로 기존 XERP 일일 데이터에서 찾아 붙인다. 찾지 못하면 빈칸으로 두고 오류로 보지 않는다.

## 판정 상태

| 상태 | 조건 | 의미 |
| --- | --- | --- |
| 정상 | XERP 공수와 PMIS 근거가 크게 어긋나지 않음 | 별도 확인 필요 없음 |
| 공수 누락 의심 | XERP 출근/퇴근 또는 PMIS 출입 기록이 있는데 XERP 공수가 `0` 또는 빈칸 | 공수가 반영되지 않았을 가능성 |
| PMIS 확인필요 | XERP 공수는 있는데 PMIS 인아웃 기록이 없음 | 출입 기록 누락 또는 이름/날짜 매칭 확인 필요 |
| 연장 확인필요 | XERP 퇴근이 17:00 이후인데 공수가 1.0 이하 | 연장/가산 공수 반영 여부 확인 필요 |
| 조출/특이출근 확인필요 | XERP 출근이 이르거나 출퇴근 조합이 일반 패턴과 다름 | 조출, 반차, 특이근무 여부 확인 필요 |
| 가산사유 확인 | 가산사유는 있는데 공수 반영이 낮거나 비어 있음 | 가산사유 반영 누락 가능성 |
| PMIS 미업로드 | 해당 날짜의 PMIS 기록 자체가 없음 | 아직 확인 대상 아님 |
| 전자카드 참고 | PMIS 근거가 부족하지만 전자카드 출퇴근 시간이 있음 | 보조 증빙으로 확인 가능 |
| 전자카드 미저장 | 해당 날짜의 전자카드 기록이 저장되지 않음 | 전자카드 증빙은 아직 없음 |

## 화면 구성

상단 요약은 표를 가리지 않도록 작게 유지한다. 큰 카드 여러 개를 늘어놓지 않고, 핵심 요약 4~5개와 작은 상태 칩 메뉴만 둔다.

상단 미니 요약:

- 확인 기간
- 전체 건수
- 확인필요
- 증빙부족
- 확인완료

상태 칩 메뉴:

- 전체
- 공수누락
- 연장
- 가산사유
- PMIS
- 전자카드
- 정상

많은 인원을 꼼꼼히 확인할 수 있도록 화면은 `요약 → 상태 메뉴 → 전체 목록 → 상세정보` 순서로 구성한다.

### 확인 작업 흐름

1. 상단 요약에서 전체 상태를 먼저 본다.
2. 위쪽 상태 메뉴에서 `전체`, `공수 누락 의심`, `연장 확인필요`, `가산사유 확인`, `PMIS 확인필요`, `PMIS 미업로드`, `정상`을 모두 볼 수 있게 한다.
3. 각 행에서 XERP 출근/퇴근, XERP 공수, 가산사유, PMIS 출근/퇴근 시간을 한 줄로 비교한다.
4. 필요하면 사람별로 펼쳐서 13일~20일 전체 흐름을 본다.
5. 확인이 끝난 행은 `확인완료`로 표시해 남은 건만 계속 볼 수 있게 한다.
6. 특이사항이 있으면 체크박스와 메모를 남겨 나중에 다시 확인할 수 있게 한다.

### 필터와 정렬

- 상태 메뉴: 전체, 공수 누락 의심, 연장 확인필요, 가산사유 확인, PMIS 확인필요, PMIS 미업로드, 전자카드 참고, 전자카드 미저장, 정상
- 상태 필터: 전체, 확인필요, 공수 누락 의심, PMIS 확인필요, 연장 확인필요, 가산사유 확인, 정상
- 날짜 필터: 기본 2026년 5월 13일~20일, 이후 날짜 범위 변경 가능
- 이름 검색
- 팀 필터
- 가산사유 있음만 보기
- PMIS 출근/퇴근 없음만 보기
- 전자카드 출근/퇴근 있음만 보기
- 전자카드 미저장만 보기
- 공수 0 또는 빈칸만 보기
- 정렬: 상태 우선순위, 날짜, 이름, 공수, 퇴근시간

상세 표:

| 상태 | 이름 | 날짜 | XERP 출근 | XERP 퇴근 | 시스템 공수 | 근무시간 | 가산사유 | PMIS 출근 | PMIS 퇴근 | 전자카드 출근 | 전자카드 퇴근 | 확인 내용 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 확인필요 | 홍길동 | 05/20 | 06:30 | 18:10 | 1.0 | 11:40 | 연장 | 06:24 | 18:16 | 06:28 | 18:14 | 연장 반영 확인 |
| 누락의심 | 김철수 | 05/20 | 06:45 | 17:05 | 0 | 10:20 | 주간 | 없음 | 없음 | 06:41 | 17:09 | PMIS는 없지만 전자카드 근거 있음 |
| PMIS확인 | 박영희 | 05/20 | 07:00 | 17:00 | 1.0 | 10:00 |  | 없음 | 없음 | 없음 | 없음 | 출입 증빙 부족 |

표는 기본적으로 `확인필요`, `공수 누락 의심`, `PMIS 확인필요`를 위에 보여주고, 정상 건은 접거나 필터로 볼 수 있게 한다.

### 행 표시 원칙

- 상태는 색상과 짧은 라벨로 표시한다.
- `확인 내용`은 사용자가 바로 판단할 수 있게 한 문장으로 쓴다.
- `가산사유`가 있으면 눈에 띄는 배지로 표시한다.
- PMIS 기록은 `출근시간`, `퇴근시간`, `없음`, `미업로드`로 구분한다.
- PMIS 출입 기록이 여러 개 있으면 최초 IN을 `PMIS 출근`, 최종 OUT을 `PMIS 퇴근`으로 보여준다.
- 같은 날짜의 PMIS 원본 로그 전체는 행 펼침에서 시간순으로 보여준다.
- 전자카드 기록은 `전자카드 출근`, `전자카드 퇴근`, `미저장`으로 구분한다.
- PMIS가 없거나 애매한 경우에도 전자카드 시간이 있으면 상세정보에서 보조 증빙으로 강조한다.
- 행을 클릭하면 상세정보가 펼쳐진다. 표에서는 핵심만 보고, 상세정보에서 가산사유/PMIS/XERP 원본 근거를 꼼꼼히 확인한다.
- 정상 행은 기본적으로 접어두되, 전체 검토가 필요하면 펼쳐 볼 수 있다.
- 한 사람에게 여러 날짜 문제가 있으면 사람별 그룹에서 묶어 보여준다.

### 사람별 펼침 보기

사람 이름을 클릭하면 해당 직원의 13일~20일 흐름을 날짜순으로 보여준다.

| 날짜 | XERP 출근 | XERP 퇴근 | 공수 | 근무시간 | 가산사유 | PMIS 출근 | PMIS 퇴근 | 전자카드 출근 | 전자카드 퇴근 | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 05/13 | 06:14 | 18:53 | 1.5 | 12:39 | 연장 | 06:11 | 18:58 | 06:12 | 18:57 | 정상 |
| 05/14 | 06:12 | 19:00 | 1.5 | 12:48 | 연장 | 06:10 | 19:05 | 06:11 | 19:01 | 정상 |
| 05/20 | 06:13 | 17:00 | 1.0 | 10:47 |  | 06:12 | 17:03 | 미저장 | 미저장 | 정상 |

이 보기에서는 날짜별 흐름이 끊기는 날, 공수가 갑자기 낮아진 날, 가산사유가 있는데 공수가 낮은 날을 쉽게 찾을 수 있어야 한다.

PMIS 출입 기록이 여러 번 있는 날은 해당 날짜를 펼치면 원본 로그를 보여준다.

| 시간 | 방향 | 게이트 |
| --- | --- | --- |
| 06:11 | IN | P4 Main |
| 11:48 | OUT | P4 Main |
| 12:37 | IN | P4 Main |
| 18:58 | OUT | P4 Main |

### 행 상세정보

상세정보는 한 행을 클릭했을 때 펼쳐진다. 많은 컬럼을 항상 노출하면 표가 복잡해지므로, 기본 표는 요약 위주로 두고 상세정보에서 근거를 확인한다.

상세정보 구성:

- XERP 월간출퇴근현황: 출근, 퇴근, 시스템 공수, 근무시간
- PMIS 요약: 최초 IN, 최종 OUT, 출입 횟수
- PMIS 원본 로그: 시간순 IN/OUT 전체
- 전자카드 요약: 출근시간, 퇴근시간, 인증방식, 저장 여부
- 가산사유: 사유명, 가져온 출처, 같은 날짜/이름 매칭 여부
- 자동 판정 근거: 왜 `공수 누락 의심`, `연장 확인필요` 등이 떴는지
- 검토 입력: 확인완료, 특이사항, 문의필요, 수정필요, 보류, 메모

예시:

| 항목 | 값 |
| --- | --- |
| 자동 판정 | 연장 확인필요 |
| 판정 근거 | XERP 퇴근 18:10, 공수 1.0, 가산사유 연장 |
| XERP 월간출퇴근현황 | 출근 06:30 / 퇴근 18:10 / 시스템 공수 1.0 / 근무시간 11:40 |
| PMIS | 최초 IN 06:24 / 최종 OUT 18:16 / 출입 4회 |
| 전자카드 | 출근 06:28 / 퇴근 18:14 / 인증 지문 |
| 가산사유 | 연장 |
| 메모 | 연장 공수 반영 여부 확인 |

### 확인완료 표시

사용자가 직접 확인한 행은 `확인완료` 체크를 할 수 있게 한다. 이 값은 브라우저 로컬 저장소에 보관해 새로고침 후에도 유지한다. 이 기능은 공수를 수정하지 않고, 검토 진행 상황만 저장한다.

### 특이사항 체크

각 행에는 검토용 체크 항목을 둔다. 이 값은 XERP 공수를 수정하지 않고, 최종 확인 과정에서 남기는 작업 메모다.

체크 항목:

- `확인완료`: 이상 없음 또는 조치 완료
- `특이사항`: 자동 판정 외에 눈으로 봐야 할 내용 있음
- `문의필요`: 현장/담당자에게 확인 필요
- `수정필요`: XERP 또는 수기 반영값 수정 필요
- `보류`: 자료가 부족해서 나중에 다시 확인

메모:

- 각 행마다 짧은 메모를 입력할 수 있다.
- 예: `PMIS는 있는데 XERP 공수 0`, `연장 사유 확인 필요`, `반차로 보임`, `현장휴무 여부 확인`
- 메모가 있는 행은 별도 필터 `메모 있음`으로 볼 수 있다.

검토 상태 필터:

- 미확인
- 확인완료
- 특이사항
- 문의필요
- 수정필요
- 보류
- 메모 있음

사람별 펼침 보기에서도 날짜별 체크 상태와 메모가 함께 보여야 한다. 그래야 같은 직원의 여러 날짜 문제를 한 번에 정리할 수 있다.

## 데이터 흐름

1. 사용자가 XERP 월간출퇴근현황 파일을 업로드한다.
2. 앱이 이름/날짜별 `출근`, `퇴근`, `공수`, `근무시간`을 파싱한다.
3. 앱이 기존 XERP 일일 데이터에서 같은 날짜/이름의 `가산사유`를 찾아 붙인다.
4. 앱이 기존 PMIS 인아웃 기록을 날짜/이름 기준으로 매칭한다.
5. 앱이 날짜별 저장된 전자카드 기록을 날짜/이름 또는 생년월일 기준으로 매칭한다.
6. 날짜별 확인 상태를 계산한다.
7. 요약 카드와 상세 표에 결과를 표시한다.

## 이름 매칭

1차 구현은 기존 앱의 이름 정규화 방식처럼 공백 제거 기반으로 매칭한다. PMIS와 XERP 이름이 다르게 들어오는 경우는 `PMIS 확인필요`로 표시하고, 이후 필요하면 이름 별칭 테이블을 추가한다.

전자카드는 이름과 생년월일을 함께 사용한다. 이름이 다르고 생년월일만 맞는 경우는 `이름불일치` 근거로 상세정보에 표시한다.

## 테스트 기준

- XERP 월간출퇴근현황 샘플에서 13일~20일 데이터를 파싱한다.
- 출근/퇴근 시간이 있는데 공수가 0이면 `공수 누락 의심`으로 판정한다.
- 퇴근이 17:00 이후이고 공수가 1.0 이하이면 `연장 확인필요`로 판정한다.
- 가산사유가 있는데 공수가 0이거나 일반 근무보다 낮으면 `가산사유 확인`으로 판정한다.
- XERP 공수가 있는데 PMIS 기록이 없으면 `PMIS 확인필요`로 판정한다.
- 해당 날짜 PMIS 데이터가 아예 없으면 `PMIS 미업로드`로 판정한다.
- PMIS는 없지만 전자카드 출근/퇴근 시간이 있으면 `전자카드 참고`로 보조 증빙을 표시한다.
- 해당 날짜 전자카드 기록이 저장되지 않았으면 `전자카드 미저장`으로 표시하되 오류로 단정하지 않는다.

## 제외 범위

- 급여대장 자동 수정
- XERP 시스템으로 자동 재업로드
- PMIS 파일 자동 수집
- 1일~12일 날짜의 오류 단정
