# XERP 근로자 등록 자동 반영 설계

## 배경

`worksite-radar`의 `기술인 및 관리자 명단`은 XERP `노무관리 > 근로자관리 > 근로자 등록` 엑셀과 직접 연결된다. 현재는 사용자가 XERP에서 엑셀을 다운로드한 뒤 앱에서 업로드하거나 수동으로 반영해야 한다. 1차 목표는 로그인 정보 저장 없이, 사용자가 이미 로그인한 로컬 브라우저 세션과 다운로드 폴더를 활용해 이 반복 작업을 줄이는 것이다.

## 1차 목표

- 대상 메뉴: XERP `노무관리 > 근로자관리 > 근로자 등록`
- 대상 현장: `평택 P4-PH4 초순수`, `평택 P4-PH2 초순수`
- 제외 현장: `P5-PH1`은 계정/비밀번호가 다르므로 1차 범위에서 제외한다.
- 결과: XERP에서 다운로드된 `근로자 등록_*.xlsx`를 `worksite-radar > 기술인 및 관리자 명단`에 반영한다.

## 비목표

- XERP 계정 ID/비밀번호 저장
- XERP 서버 API 직접 호출
- XERP 전체 메뉴 자동화
- P5-PH1 계정 전환 자동화
- 사용자의 확인 없이 기존 명단을 조용히 덮어쓰기

## 접근 방식

권장 구조는 `브라우저 자동 클릭 + 다운로드 파일 감시 + 기존 엑셀 파서 재사용`이다.

1. 사용자가 로컬 브라우저에서 XERP에 직접 로그인한다.
2. `worksite-radar`에서 `XERP 근로자 가져오기`를 실행한다.
3. 로컬 헬퍼가 현재 로그인된 XERP 브라우저를 사용해 `근로자 등록` 화면에서 현장을 선택한다.
4. `조회` 후 `엑셀` 버튼을 눌러 다운로드를 시작한다.
5. 로컬 헬퍼가 `Downloads` 폴더에서 새로 생성된 `근로자 등록_*.xlsx` 파일을 감지한다.
6. 앱은 기존 `parseImportedSheet` 로직으로 엑셀을 읽고, 사용자가 확인한 뒤 해당 현장 탭 명단을 갱신한다.

자동 클릭이 실패해도 사용자가 직접 XERP에서 엑셀을 다운로드하면 같은 파일 감시/반영 로직이 동작해야 한다.

## 사용자 흐름

### PH4 반영

1. 사용자가 XERP에 로그인한다.
2. `worksite-radar`에서 `기술인 및 관리자 명단 > XERP 가져오기`를 누른다.
3. 현장 선택값은 `평택 P4-PH4 초순수`로 설정된다.
4. 헬퍼가 XERP `조회`와 `엑셀` 다운로드를 수행한다.
5. 앱이 신규 다운로드 파일을 감지하고 미리보기/반영 확인을 표시한다.
6. 사용자가 확인하면 `P4-PH4 초순수` 탭 데이터가 갱신된다.

### PH2 반영

PH4와 동일한 흐름을 사용하되 현장 선택값은 `평택 P4-PH2 초순수`, 반영 대상 탭은 `P4-PH2 초순수`다.

## 데이터 매핑

기존 파서는 XERP 근로자 등록 양식의 주요 컬럼을 다음처럼 읽는다.

- `성명` -> `이름`
- `주민등록번호` -> `주민번호`
- `성별` -> `남여`
- `연락처` -> `연락처`
- `기본주소` -> `주소`
- `소속팀` -> `현장구분`
- `직종` -> `신청공종`
- `입사일` -> `입사일`
- `퇴사일` -> `퇴사일`
- `노임` -> `단가변동`
- `은행` -> `은행명`
- `계좌번호` -> `계좌번호`
- `단가` -> `단가`

동명이인은 이미 이름 셀에 `동명이인` 배지로 표시한다. 자동 반영 후에도 같은 표시가 유지되어야 한다.

## 로컬 헬퍼 경계

Vercel에서 배포된 웹 앱은 사용자의 로컬 브라우저나 다운로드 폴더를 직접 제어할 수 없다. 따라서 자동 다운로드에는 로컬 헬퍼가 필요하다. 기존 프로젝트의 로컬 서비스 패턴을 따른다.

- 앱: 사용자의 명령, 상태 표시, 파일 파싱, 반영 확인
- 로컬 헬퍼: XERP 브라우저 제어, 다운로드 감시, 파일 전달
- Firestore: 반영된 명단 저장

## 오류 처리

- XERP 창을 찾지 못하면: `XERP에 로그인한 Chrome/Edge 창을 열어주세요.`
- 근로자 등록 화면이 아니면: `노무관리 > 근로자관리 > 근로자 등록 화면으로 이동해 주세요.`
- 현장 선택 실패: 사용자가 직접 현장을 선택하고 다시 실행할 수 있게 한다.
- 다운로드 실패: 직접 `엑셀` 버튼을 눌러 다운로드하면 감시 로직이 이어받는다.
- 파싱 결과 0명: 파일 양식 오류로 보고 반영하지 않는다.
- 기존 명단 덮어쓰기 전: 인원 수, 재직/퇴사 수, 동명이인 수를 보여주고 확인을 받는다.

## 구현 단위

1. XERP 현장 상수
   - `PH4`: `평택 P4-PH4 초순수`
   - `PH2`: `평택 P4-PH2 초순수`

2. 다운로드 감시
   - `Downloads`에서 `근로자 등록_*.xlsx` 최신 파일을 감지한다.
   - 실행 시작 시각 이후 생성/수정된 파일만 후보로 본다.

3. 로컬 헬퍼 API
   - `GET /xerp-worker-registration/status`
   - `POST /xerp-worker-registration/download` with `{ site: "PH4" | "PH2" }`
   - `GET /xerp-worker-registration/latest?site=PH4`

4. 앱 UI
   - 기술인 및 관리자 명단 툴바에 `XERP 가져오기` 버튼 추가
   - PH4/PH2 탭별로 실행
   - 자동 다운로드 진행 상태와 수동 다운로드 fallback 안내 표시
   - 반영 전 요약 모달 표시

5. 저장
   - 사용자가 확인한 뒤 기존 `saveEmployeesPH4FS`, `saveEmployeesPH2FS`를 호출한다.
   - 이름 없는 행은 기존 `sanitizeEmployeeRows` 기준으로 제외한다.

## 테스트 전략

- 파일 감시: 시작 시각 이후 생성된 최신 `근로자 등록_*.xlsx`만 선택하는 단위 테스트
- 파싱: XERP 근로자 등록 양식 샘플이 기존 `NewEmployeeList` 필드로 들어가는 테스트
- UI: 자동 반영 전 요약에 총 인원/재직/퇴사/동명이인 수가 표시되는 테스트
- 헬퍼 실패: XERP 창 없음, 다운로드 없음, 파싱 실패 상태 메시지 테스트

## 배포 전략

1차 구현은 로컬 헬퍼와 웹 앱 변경을 같은 브랜치에서 진행한다. 운영 반영 전에는 PH4 파일 하나로 수동 다운로드 fallback을 먼저 검증하고, 그 다음 자동 클릭을 검증한다. PH2는 같은 흐름의 두 번째 현장으로 검증한다.
