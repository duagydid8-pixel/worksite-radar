# 전자카드 자동 동기화 설계

날짜: 2026-05-21

## 목표

건설근로자공제회 `eum.cw.or.kr`의 전자카드사용내역을 사용자가 파일로 내려받아 업로드하지 않아도, 로그인된 브라우저 세션을 이용해 자동으로 가져와 앱 데이터에 반영한다. 사용자는 공제회 사이트에 로그인만 유지하고, 이후에는 "전자카드 1일부터 오늘까지 갱신해줘"라고 요청하면 된다.

## 확정된 사용 방식

- 사용자는 `eum.cw.or.kr`에 로그인해둔다.
- 최초 1회, 전자카드사용내역 화면에서 원하는 `현장`과 `소속 업체명`을 선택해둔다.
- 자동화는 현재 화면에서 선택된 현장명과 체크된 소속 업체명을 읽어서 로컬 설정으로 저장한다.
- 현재 기준 소속 업체명은 화면에 체크된 2개 업체를 모두 사용한다.
- 이후 실행 시 자동화는 저장된 현장과 업체 2개를 다시 선택한다.
- 조회 기간은 매번 해당 월 1일부터 실행 당일 날짜까지로 설정한다.
- 조회 후 전자카드 기록을 가져와 Firestore에 날짜별로 저장한다.

## 화면 흐름

1. 로그인된 브라우저에서 전자카드사용내역 화면으로 이동한다.
2. 저장된 `현장` 값을 현장 드롭다운에서 선택한다.
3. 저장된 `소속 업체명` 값을 소속 업체명 다중 선택 목록에서 모두 체크한다.
4. 근로기간 시작일을 해당 월 1일로, 종료일을 오늘로 설정한다.
5. 조회 버튼을 누른다.
6. 조회 결과를 엑셀 저장 또는 화면 테이블 수집 방식으로 가져온다.
7. 앱에서 쓰는 전자카드 행 구조로 정규화한다.
8. Firestore에 날짜별 문서와 인덱스를 갱신한다.

## 설정 저장

설정은 자동화 스크립트가 읽을 수 있는 로컬 파일로 저장한다. 값은 사람이 확인하기 쉬워야 하며, 비밀번호나 로그인 토큰은 저장하지 않는다.

저장 항목:

- 현장 표시명
- 소속 업체명 표시명 배열
- 마지막 설정 저장 시각
- 전자카드 조회 화면 URL 또는 메뉴 식별자

저장하지 않는 항목:

- 공제회 아이디와 비밀번호
- 브라우저 쿠키나 세션 토큰 원문
- 엑셀 파일 비밀번호 외의 민감 정보

## 데이터 정규화

기존 전자카드 엑셀 파서가 사용하는 필드에 맞춘다.

- 성명
- 생년월일
- 출근 시간
- 퇴근 시간
- 인증 방식
- 소속 업체명
- 현장명
- 조회 날짜

엑셀 파일이 비밀번호로 보호된 경우 기존 처리와 동일하게 `1234`를 사용한다.

## Firestore 저장 구조

PMIS IN/OUT 로그와 비슷하게 날짜별 저장을 기본으로 한다.

- 날짜별 문서: `electronic_card_ph4_YYYY-MM-DD`
- 인덱스 문서: `electronic_card_ph4_index`

날짜별 문서는 해당 날짜의 전자카드 행 목록, 저장 시각, 원본 출처 정보를 가진다. 인덱스 문서는 저장된 날짜 목록과 마지막 동기화 범위를 가진다.

다시 실행할 때는 같은 월 1일부터 오늘까지 전체를 재동기화한다. 같은 날짜 문서는 최신 조회 결과로 교체해서 중복을 만들지 않는다.

## 실패 처리

- 로그인 세션이 만료되어 로그인 페이지로 이동하면 "전자카드 로그인 다시 필요"로 중단한다.
- 저장된 현장명이 드롭다운에 없으면 설정 불일치로 중단한다.
- 저장된 소속 업체명 중 하나라도 목록에 없으면 설정 불일치로 중단한다.
- 조회 결과가 0건이면 해당 날짜를 임의로 빈 데이터로 저장하지 않고 경고에 남긴다.
- 엑셀 다운로드가 막히면 화면 테이블 수집으로 대체할 수 있게 수집 단계를 분리한다.
- 공제회 사이트 구조가 바뀌면 선택자 오류를 명확히 출력한다.

## 앱 연동

현재 앱의 전자카드 조회 화면은 파일 업로드 기반 파싱을 지원한다. 자동화는 같은 정규화 결과를 만들고 Firestore에 저장해서, 최종공수확인 화면이 별도 파일 업로드 없이 전자카드 증빙을 사용할 수 있게 한다.

앱 화면에서 필요한 변화:

- 저장된 전자카드 데이터 로드 함수 추가
- 전자카드 데이터가 저장된 날짜와 미저장 날짜 표시
- 최종공수확인에서 PMIS와 전자카드 증빙을 함께 비교

## 검증 기준

- 저장된 설정 파일에 현장명과 소속 업체명 2개가 정확히 들어간다.
- 로그인된 상태에서 월 1일부터 오늘까지 조회가 실행된다.
- Firestore 인덱스에 저장된 날짜 목록이 조회 기간과 일치한다.
- 날짜별 문서에 같은 사람의 전자카드 출근과 퇴근 시간이 보존된다.
- 같은 기간을 두 번 실행해도 중복 행이 생기지 않는다.
- 로그인 만료, 현장명 불일치, 업체명 불일치가 각각 명확한 오류로 멈춘다.

## 제외 범위

- 공제회 사이트 자동 로그인
- 공제회 계정 정보 저장
- 전자카드 기록의 수동 수정 UI
- XERP 공수 자동 수정
- PMIS 자동화 구조 변경
